# Как воспроизвести

Два пути.

- **Путь A** собирает отправленный файл из готовых предсказаний компонентов: секунды,
  ноутбук, без GPU, данные площадки не нужны. Результат совпадает с тем, что ушло на
  площадку, **до машинной точности**.
- **Путь B** обучает все 13 моделей с нуля из `train.parquet`: нужен GPU, порядка
  15 GPU-часов и 8 CPU-часов. Бит-в-бит здесь невозможен, подробнее в §4.

Что делает каждая модель и какими командами обучается — в [`MODELS.md`](MODELS.md).

---

## 1. Что уже есть и что нужно принести

Для пути A доставлять нечего:

| что | где | размер |
|---|---|---|
| предсказания 13 компонентов | `reference/` | 77 МБ |
| отправленный финальный файл | `reference/e0303_arch4_cal.csv` | 6.3 МБ |
| замороженное разбиение на фолды | `data/folds.parquet`, `data/fold_spec.json` | 4.4 МБ |
| код, конфиги, сборщик | `src/`, `configs/`, `solution/` | — |

Для пути B нужны данные, они кладутся в `data/` **без изменений**:

| файл | куда | обязателен |
|---|---|---|
| `train.parquet` | `data/train.parquet` | да |
| `sample_submission.csv` | `data/sample_submit.csv` | нет — без него пропускается сверка множества `user_id` |

Проверить, что подложен нужный файл: 30 631 006 строк, 250 000 уникальных `user_id`,
даты 2025-01-01 … 2026-02-13 — команда в корневом [`README.md`](../README.md), раздел «Данные».

**Разбиение пересчитывать не нужно.** Готовое едет с репозиторием, и `run.sh all` его не
трогает — иначе каждый запуск подменял бы разбиение, на котором измерены все эксперименты.
Если хотите убедиться, что оно воспроизводится из `train.parquet`:

```bash
bash run.sh folds        # ПЕРЕЗАПИШЕТ data/folds.parquet; содержимое обязано совпасть
```

Проверено: хеш содержимого `7a72cbf9f957d9a2` получается одинаковым на разных стеках, при
том что байты самого parquet отличаются — это разные версии писателя, а не разные данные.

## 2. Окружение

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r solution/requirements.txt          # путь A: numpy, polars, pandas, pyarrow
pip install -r solution/requirements-full.txt     # путь B: + torch, lightgbm, optuna, autogluon
```

Python 3.9+. Скрипты берут интерпретатор из переменной `PY`:

```bash
PY=./.venv/bin/python bash run.sh quick
```

Проверялось на двух несовпадающих стеках, оба дали одинаковый результат:

| | стек 1 | стек 2 |
|---|---|---|
| python | 3.9.6 | 3.13.5 |
| numpy / polars | 1.26 / 1.36 | 1.26 / 1.44 |
| torch | 2.8.0 | 2.13.0+cu130 |
| lightgbm / autogluon | 4.6.0 / 1.4.0 | 4.7.0 / 1.6.1 |

## 3. Путь A — собрать отправленный файл

```bash
bash run.sh quick
```

Ожидаемый вывод:

```
== сборка сабмита из ЭТАЛОННЫХ предсказаний компонентов (reference/)
=== e0303_arch4_cal   public LB 1.646483   ФИНАЛЬНОЕ РЕШЕНИЕ
  слот gbdt   w=0.20  2 чл.  mu 2.4446 sd 1.5707   e0266, e0064
  слот seq    w=0.38  7 чл.  mu 2.5123 sd 1.5874   e0100, e0101, ...
  слот usercv w=0.42  4 чл.  mu 2.3397 sd 1.5786   e0141, e0295_usercv48, e0340_lstm48, e0341_xf48
  сырой бленд          mu 2.4263 sd 1.5787
  калибровка           L = 1.032894815*M -0.175361702
  после калибровки     mu 2.3307 sd 1.6306
  self-test vs reference/e0303_arch4_cal.csv (md5 dc530023): corr 1.0000000  rms 0.000000
  OK — БИТ-В-БИТ то, что ушло на площадку
готово: submission/e0303_arch4_cal.csv
```

Скрипт возвращает код 1, если self-test не сошёлся, — годится для CI.

Точность: `rms(Δlog) = 8.6e-16`, максимальная относительная разница предсказаний `1.8e-10`.
Побайтово csv при этом **не** идентичен отправленному: расходится последняя значащая цифра при
печати float в текст, а это свойство версии Python. Сверять надо числа, а не байты — сборщик
так и делает.

Проверить формат готового файла и тай-брейкеры жюри (Gini, суммарный GMV):

```bash
python solution/verify_submission.py submission/e0303_arch4_cal.csv
```

## 4. Путь B — обучить с нуля

```bash
bash run.sh all           # gbdt -> seq -> usercv -> сборка
bash run.sh seq           # или по одному слоту
```

Команды по слотам, ресурсы и измеренные CV — в [`MODELS.md`](MODELS.md). Каждый прогон CV
пишет OOF в `oof/<exp_id>.parquet` и строку в `experiments.csv`; предсказания на тесте
попадают в `subs/`.

**Обучение пишет в `subs/`, а `reference/` не трогает.** Поэтому после `run.sh all` собирать
надо командой `bash run.sh blend` — она возьмёт ваши компоненты, а сравнит с отправленным
файлом из `reference/`.

### Чего ожидать по числам

Нейросетевые члены **не бит-в-бит детерминированы**: `torch.manual_seed` зафиксирован,
`cudnn.deterministic` — нет. Измерено на этом репозитории: член `e0101` переобучен с нуля на
другой машине и другом стеке (A100 вместо H200, torch 2.13 вместо 2.8, python 3.13 вместо 3.9):

| что сравнивается | corr | rms(Δlog) |
|---|---|---|
| переобученный `e0101` против отправленного | 0.998287 | 0.0940 |
| **итоговый файл** с этим членом вместо эталонного | **0.999995** | 0.00526 |

Один переобученный член из тринадцати сдвигает результат на `rms 0.005` в лог-пространстве:
усреднение по слоту гасит разброс в 18 раз — член ушёл на 0.094, файл на 0.005.

Порог приёмки перестроенного бленда — **corr ≥ 0.9999** против отправленного файла;
`bash run.sh blend` проверяет именно его и бит-в-бит не требует:

```
self-test vs reference/e0303_arch4_cal.csv: corr 0.9999949  rms 0.005263
OK — собрано из ВАШИХ переобученных компонентов, corr 0.999995 с отправленным файлом
```

Табличная часть (LightGBM) детерминирована при фиксированных сидах и числе раундов;
AutoGluon — нет, он выбирает состав ансамбля по своей внутренней валидации.

**Если сошлось хуже порога** — смотрите по слотам, а не по итоговому файлу: сборщик печатает
`mu` и `sd` каждого слота, и расхождение локализуется за одну итерацию.

## 5. Что именно проверено

| проверка | где | результат |
|---|---|---|
| `run.sh quick` из чистого клона и чистого venv | ноутбук | бит-в-бит |
| то же на другом стеке | кластер, python 3.13 / torch 2.13 | бит-в-бит |
| `run.sh folds` из `train.parquet` | ноутбук и кластер | содержимое совпало, `7a72cbf9f957d9a2` |
| обучение члена слота seq с нуля | кластер, A100 | 5 фолдов CV + предсказание, 8 минут |
| сборка из переобученного компонента | ноутбук | corr 0.999995, код возврата 0 |

Полный `run.sh all` — все 13 моделей за один прогон — не запускался: это порядка 15 GPU-часов.
Проверен один член из тринадцати, но он тянет за собой весь общий путь: `data.py`, `folds.py`,
`seqdata.py`, `seqnet.py`, чтение конфига, запись OOF и предсказание на тесте.
