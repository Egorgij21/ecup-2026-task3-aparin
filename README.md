# E-CUP 2026 · Задача 3 — «Ценность пользователей» (Ozon Tech)

Предсказание суммарного GMV каждого из 250 000 пользователей за 30 дней
(2026-02-14 → 2026-03-15) по 30.6 млн записей дневной активности. Метрика — RMSLE.

**Приватный лидерборд: 1.6616, 3-е место.**
Публичный: **1.6464** — файл `e0303_arch4_cal`, который этот репозиторий и собирает.
(Вторым сабмитом был выбран `e0300_cal` — тот же пайплайн, отличается только содержимым одного
слота. Здесь он не воспроизводится.)

## Данные

В репозитории лежат **замороженные фолды** (`data/folds.parquet`, `data/fold_spec.json`) —
разбиение, на котором измерены все эксперименты проекта.

Самих данных соревнования здесь нет. Они нужны **только для обучения с нуля** — сборка
готового сабмита происходит без них:

| файл | куда положить | зачем |
|---|---|---|
| `train.parquet` | `data/train.parquet` | обучение 13 моделей (`bash run.sh all`) |
| `sample_submission.csv` | `data/sample_submit.csv` | сверка множества `user_id` в готовом сабмите |

> Без `data/sample_submit.csv` всё работает, только пропустится проверка по множеству `user_id`. Порядок при этом всё равно перекрёстно
> проверяется между всеми предсказаниями компонентов.

## 1. Что в бленде

Взвешенное среднее трёх слотов в **лог-пространстве** плюс аффинная калибровка:

```
prediction = expm1( a · [ 0.20·log1p(gbdt) + 0.38·log1p(seq) + 0.42·log1p(usercv) ] + b )
```

Внутри слота члены усредняются равными весами, тоже в логах. Лог-пространство — потому что
оптимальный точечный прогноз для RMSLE есть `E[log1p(y)|x]`.

| слот | вес | что это | членов |
|---|---|---|---|
| **gbdt** | 0.20 | LightGBM на 665 инженерных признаках (3 сида) + AutoGluon на отфильтрованных 400 | 2 |
| **seq** | 0.38 | причинные TCN / GRU / трансформер на **сырых** 13 дневных каналах, без инженерных признаков | 7 |
| **usercv** | 0.42 | рекуррентные модели с разбиением по пользователям — обучаются на календаре на 4 месяца дальше остальных | 1–4 |

Три слота — это три разных взгляда на одни и те же данные: признаковый, последовательностный
на сыром ряде и последовательностный на пользовательском сплите. Смешивание даёт ≈0.009 RMSLE
против лучшей одиночной модели — это главный источник качества.

**Веса подобраны один раз на OOF и больше не пересчитывались.** Три попытки перевзвесить по
CV/OOF проиграли на лидерборде (`e0270` −0.00010, `e0302` −0.00026, `e0303` — обе с инверсией
знака относительно прогноза CV), а две замены *содержимого* слота при неизменных весах
спрогнозировались с точностью 1e-6 и 2e-6. При корреляции членов 0.998 подгонка весов
извлекает шум CV, а не сигнал.

**Калибровка даёт ≈0.005 RMSLE** — больше, чем любое улучшение модели. После аффинного
преобразования в логах метрика зависит ровно от одной величины: `RMSLE = sd_L·sqrt(1 − ρ²)`, где
`L = log1p(y_true)`. Моменты тестовой выборки получены в закрытом виде из двух probe-сабмитов:
всех нулей (`RMSLE² = E[L²]`) и константы 10 (`RMSLE² = E[L²] − 2c·E[L] + c²`), откуда
`E[L] = 2.3303`, `sd_L = 2.3178`.

Полный перечень 13 моделей с конфигами, ресурсами и измеренными числами —
**[`solution/MODELS.md`](solution/MODELS.md)**.

## 2. Как обучить и провалидировать

### Протокол валидации

**Замороженные фолды** — `data/folds.parquet`, генератор `src/folds.py`. Расширяющееся окно,
5 валидационных якорей. Менять их нельзя: на них измерены все эксперименты проекта, и другое разбиение делает
прежние числа несравнимыми. Три правила, каждое измерено:

- **Популяция на якоре A** — пользователи хотя бы с одним активным днём в `[A−29, A]`. Это
  воспроизводит правило включения теста: `E[log1p y]` = 2.330 против измеренного по LB 2.320.
  Оценивать всех 250k на прошлом якоре оптимистичнее на ~0.10.
- **Зона гарантированной активности** `[2025-11-16, 2026-02-13]`: окно таргета не должно её
  касаться, поэтому последний чистый якорь — 2025-10-16. Внутри неё 100 % пользователей активны
  по построению, и обучение там решает не ту задачу.
- **Разрыв** `A_train ≤ A_valid − 30`, чтобы ни одно обучающее окно таргета не заходило за
  валидационный якорь.

**User-split** — разбиение по `user_id` (md5, соль `gmv-v1`). Позволяет обучаться на календаре до 2026-01-14.

**Порог значимости.** Шумовой пол измерен пятикратным прогоном бейзлайна с разными сидами.
Изменение считается реальным только при `|Δ| > 2σ_noise` **или** победе на ≥4/5 фолдах. Дельты
внутри шума не накапливаются — именно так переобучают собственный CV.

### Обучение

```bash
# слот GBDT — CPU, ~7.5 ч
python src/run_regime.py --config configs/e0260_regime.yaml
python src/predict_seeds.py --config configs/e0260_regime.yaml --arm e0266 --out e0266
python src/run_ag.py --config configs/e0060_filt_top400.yaml --exp-id e0064 --mode full \
       --presets medium_quality --time-limit 9000 --cache

# слот SEQ — 1 GPU, ~40 мин на все семь моделей
for c in e0100_seq_tcn e0101_seq_gru e0101s1_seed e0101s2_seed e0101s3_seed \
         e0102_seq_xformer e0108_gru_deep; do
    python src/run_seq.py --config configs/$c.yaml                 # CV + OOF
    python src/run_seq.py --config configs/$c.yaml --mode submit   # предсказание на тесте
done

# слот USERCV — 1 GPU, 1–3 ч на модель
python src/run_usercv.py --variant full --folds 0 1 2 3 4 --seeds 3
python src/predict_usercv.py --variant full --exp-id e0141          --model gru         --hidden 128 --seeds 3 --epochs 0
python src/predict_usercv.py --variant full --exp-id e0295_usercv48 --model gru         --hidden 48  --seeds 3 --epochs 32
python src/predict_usercv.py --variant full --exp-id e0340_lstm48   --model lstm        --hidden 48  --seeds 3 --epochs 32
python src/predict_usercv.py --variant full --exp-id e0341_xf48     --model transformer --hidden 48  --seeds 3 --epochs 32
```

Каждый прогон CV пишет OOF в `oof/<exp_id>.parquet`, предсказания на тесте — в `subs/`.
Детали, ресурсы и измеренные CV по каждой модели — в [`solution/MODELS.md`](solution/MODELS.md).

⚠ Нейросетевые члены **не бит-в-бит детерминированы** (`cudnn.deterministic` выключен).
Измерено: член `e0101`, переобученный на другой машине и другом стеке, дал corr **0.998287**
с отправленным, а итоговый файл с ним вместо эталонного — corr **0.999995**. Усреднение по
слоту гасит разброс в 18 раз. Порог приёмки перестроенного бленда — corr ≥ 0.9999.

## 3. Как собрать сабмит

```bash
python solution/build_submission.py                            # собрать и сверить
python solution/build_submission.py --out-dir submission       # записать файл
python solution/verify_submission.py submission/e0303_arch4_cal.csv   # проверить
```

Сборщик берёт 13 предсказаний компонентов (по умолчанию из `reference/`, с ключом
`--components-dir subs` — из ваших), усредняет по слотам в логах, складывает с весами
`0.20 / 0.38 / 0.42`, применяет аффинную калибровку и сверяет результат с
`reference/e0303_arch4_cal.csv`. Возвращает код 1 при расхождении — годится для CI.

Слот `usercv` здесь — среднее четырёх моделей (`e0141`, `e0295_usercv48`, `e0340_lstm48`,
`e0341_xf48`); `reference/e0303_arch4_cal.csv` лежит в репозитории как эталон, с которым сборщик
сверяет результат.

Совпадение с отправленными байтами проверено на двух несовпадающих стеках — Python 3.9 / numpy
1.26 и Python 3.13 / numpy 2.2 — с одинаковым результатом rms(Δlog) ~1e-15. Побайтово csv не
идентичен: расходится последняя цифра при печати float в текст, это свойство версии Python.

Подробный runbook, включая полный путь с нуля — [`solution/REPRODUCE.md`](solution/REPRODUCE.md).
